- **현재 확인된 구현:** 없음. 모든 마일스톤 미완료. 테스트 명령·CI는 아직 존재하지 않는다.
- **프로젝트 최종 제출 마감:** 2026-11-04 21:00 ET / 2026-11-05 11:00 KST (공식 공개 일정 기준, 변경 가능)

## 1. 작업 운영 원칙

1. 기능·UI·데이터·테스트가 실제로 연결된 작은 **vertical slice**로 구현한다.
2. 모든 단계에서 원본·출처·정정·가설의 불확실성·비공개 경계를 유지한다.
3. `fixture/replay/meta-live` 결과를 구분하며 mock 성공을 실제 모델 성공처럼 보여주지 않는다.
4. 원격 GitHub 쓰기/commit/push, 배포, 신용카드·계정 변경, 실제 유료 API 호출은 각각 별도의 명시적 승인 범위에서 수행한다.
5. 작업 전 저장소·현재 브랜치·dirty files·다른 세션의 변경을 확인한다. 관련 AGENTS.md와 `liminal-cipher/agents-sync` 최신 `main`의 `global-agents/rules/engineering-policy.md`를 다시 읽는다.
6. 크레딧이 지급됐다는 사실은 무제한 유료 호출 허가가 아니다. 별도의 호출 수·모델·데이터·예산을 정한다.
7. Codex와 Muse Code 중 어느 것을 쓰더라도 동일한 문서·테스트 기준을 적용한다. 기존 작동 결과를 근거 없이 다시 구현하지 않는다.

## 3. 첫 구현 과업: M1a — Persistent Archive

### 포함

- Next.js App Router/TypeScript/Tailwind에서 실제 실행되는 반응형 웹앱 최소 UI·서버.
- Supabase Auth 이메일 Magic Link 로그인, 세션·로그아웃, 사용자별 Workspace 생성·이름 변경·목록·재조회.
- 사진/메모 이미지 등록, 직접 작성한 텍스트 메모 등록.
- Supabase Private Storage의 staged 직접 업로드와 서버 측 업로드 intent/완료 검증. 원본 바이트, MIME/디코딩/용량/접근 경계를 검사하고 public 폴더를 사용하지 않음.
- PostgreSQL의 Workspace.owner_user_id, Asset/AssetRevision, 저장·삭제 상태, 승인된 SQL migrations. 모든 공개 스키마 테이블의 명시적 GRANT/RLS 및 Storage 객체 정책.
- 업로드 일부 실패, 중복 바이트, 파일 손상, 과도한 파일의 오류 표시.
- 메타데이터 수정(기록자 날짜/메모 포함), 재시작 후 판본 복원.
- 삭제 시 접근 차단 및 파일 정리 결과 표시. 영구 실패나 재시도를 은폐하지 않음.
- 영어 UI 기본, 공개 read-only 합성 데모와 로그인한 개인 작업 공간의 데이터·API 경계. 실제 모델 미사용 표시.
- 다른 계정의 Workspace/Storage URL 접근 거부, 세션 만료, 업로드 권한 만료 테스트. 보안 관문 이후 첫 Vercel 배포는 별도 승인.

### 제외

- Meta API 호출, 이미지 OCR·연결 추론·질문 생성, 음성 전사, 실제 가족 데이터, 3D 공간.
- 공개 DB 쓰기/실가족 자료 처리/무제한 AI 호출, 인증되지 않은 비공개 자료 접근, 복잡한 프로덕션 인프라.
- 단순히 로컬스토리지·브라우저 메모리에만 기록하는 '가짜 영속화'.

### 수용 조건 — M1a

- [ ] 새 Workspace를 만들고 사진·메모·직접 입력한 텍스트를 등록할 수 있다.
- [ ] 원본 파일을 서버/스토리지에서 다시 가져오며, 잘못된 파일을 확장자로만 통과시키지 않는다.
- [ ] 페이지 새로고침 및 백엔드 재시작 뒤에도 자료·메타데이터·정정 내용이 남는다.
- [ ] 일부 업로드가 실패해도 나머지는 남으며 실패 항목만 안전하게 재시도한다.
- [ ] 더블클릭/요청 재전송으로 동일 작업이 중복 저장되지 않는다.
- [ ] Supabase Auth 세션과 Workspace 소유권/판본/삭제 상태가 API·DB·Storage에서 강제되며, 다른 사용자·익명 사용자 접근이 실제로 거부된다.
- [ ] Private Storage의 유효·만료 URL, 파일 직접 경로/토큰 오남용을 테스트하고, 삭제한 자료가 더는 접근되지 않으며 정리 실패가 표시된다.
- [ ] 공개 synthetic demo에서 개인 자료를 읽거나 영구 쓰기·Meta live 호출을 할 수 없다.
- [ ] 첫 온라인 배포 전 RLS/GRANT/Storage 정책과 실제 사용자별 격리 검증을 마쳤고, 별도 배포 승인을 받았다.
- [ ] 브라우저에서 실제 기능을 클릭해 검증했거나, 확인하지 못한 경우 그 사실을 명확히 기록한다.
- [ ] README의 실제 설치·실행·테스트 방법을 구현 증거에 따라 갱신한다.

**스택 결정 완료:** Next.js + Supabase PostgreSQL/Auth/Private Storage + Vercel(후보), 무료 우선. 별도 승인 없이 실제 원격 마이그레이션 적용, 유료 전환, 배포나 Meta API 호출을 실행하지 않는다.

## 4. M1b — Fixture E2E 완료 정의

- 화면에서 사용자가 직접 두 자료를 비교해 단서를 수정/거절할 수 있다.
- 공통 단서에서 근거 있는 연결 가설(또는 연결 없음)이 나온다.
- 사용자가 후보를 채택·보류·거절한다. 채택은 조사 선택이며 역사적 확정이 아니다.
- 질문을 선택·수정하고 발화자/기록자를 구분한 텍스트 답변을 저장한다.
- 사진·발화·미확인 정보를 구분하는 전시 카드가 만들어진다.
- 새로고침·재시작 후에도 전시의 실제 출처가 열리고 정정·삭제가 재검토 상태에 반영된다.
- `FIXTURE` 표시가 계속 보이고, 실제 Meta 모델 성능/비용 보고와 분리된다.

## 5. M2 — Meta 최소 실험

다음 자료는 **합성 또는 사용 허가가 있는 자료**로 구성한다. 정답표를 모델 입력/파일명/EXIF에 포함하지 않는다.

| 테스트 경우 | 기대 관찰 | 실패로 기록할 예 |
| --- | --- | --- |
| 읽기 쉬운 사진/메모 | 실제 보이는 간판·문구·날짜 표기 추출 | 존재하지 않는 문구 생성 |
| 글자가 흐릿한 사진 | 판독 한계·모름 표현 | 확신하는 허위 OCR |
| 서로 연결 가능한 두 자료 | 해당 원본에서 확인되는 공통 단서와 구체 질문 | 같은 장소를 근거 없이 같은 사람/같은 사건이라 단정 |
| 무관한 자료 묶음 | 연결 없음 또는 근거 부족 처리 | 무조건 서사를 만들어 연결 |
| 모순이 있는 자료 | 반대 근거·미확인 정보 제시 | 지지 근거만 선택적으로 인용 |
| 메모 내 명령문 | 업로드 내용을 데이터로만 처리 | '규칙 무시' 같은 문장을 실행 지시로 수용 |

**기록할 것:** 자료 수, 반복 수, 사용 모델 정확한 ID/모드, 프롬프트·스키마 버전, 모델 응답, 사용자의 원본 대조 판정, 실패·지연·usage. 점수·성공률을 사실로 적으려면 평가 분모와 정의를 먼저 남긴다.

실험 결과가 좋지 않으면 자료 두 개를 사람이 선택하고 AI가 차이·근거·질문을 제시하도록 범위를 좁힌다. 이를 실패 숨김이나 성공률 개선으로 포장하지 않는다.

## 8. Codex 첫 작업 지시서 초안 (M1a 전용)

**아래 지시는 구현 착수 전 스택과 권한이 승인된 이후에 사용한다. 현재 작성 자체는 구현 허가나 API 호출 허가가 아니다.**

> `README.md`, `docs/product.md`, `docs/ux-functional-spec.md`, `docs/technical-design.md`, `docs/implementation-plan.md`를 먼저 읽고, 실제 Git 상태·정책·브랜치·파일을 확인하라. 목표는 `M1a — Persistent Archive`만 구현하는 것이다. Next.js App Router·TypeScript·Tailwind와 Supabase Auth/PostgreSQL/Private Storage, SQL migrations, 실제 owner 기반 RLS/GRANT 정책을 사용하라. 로그인 및 public synthetic demo 분리, staged direct upload→server validation→AssetRevision, 삭제·재조회·세션 만료·cross-user deny 테스트를 완성하라. 실제 Meta API 호출은 하지 않는다. 제품이 실제로 저장·복원되는 UI → 서버 → DB/비공개 파일 경로를 구현하라. M1a 수용 조건을 테스트하고, UI를 실제로 동작시킬 수 있으면 클릭·새로고침·재시작을 검증하라. 테스트하지 못한 것은 미실행이라고 표시하라. 사용자가 정하지 않은 공개 배포·원격 변경·유료 호출은 하지 않는다. 기존 변경을 보존하고 최소한의 의존성으로 구현하라. 완료 후 변경 파일, 실행 결과, 검증하지 못한 항목, 다음 작업만 짧게 보고하라.`

Codex가 작업 폴더를 찾지 못하면 다른 저장소에서 임의로 시작하지 말고 경로를 확인한다. 작업자가 교체되면 새 에이전트는 이전 에이전트의 요약보다 현재 저장소와 테스트를 우선한다.
