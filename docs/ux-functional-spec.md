# Trace & Tell — UX & Functional Spec

- **상태:** v0.2 · 배포/접근 경계 합의 · 구현 전 · 2026-10-28
- **범위:** 첫 E2E 웹앱의 화면, 사용 동작, 저장 결과, 실패 경로
- **참조:** [PRD](product.md) · [Technical Design](technical-design.md) · [E2E Criteria](implementation-plan.md)
- **Figma:** https://www.figma.com/design/a4nRD7Ixyy2ue7mAL0meZU

이 문서의 화면 설명은 **구현 명세 초안**이다. Figma에 실제 존재하는 것은 `SCR-02`와 `SCR-04`의 시각 초안뿐이다. 화면 디자인이 존재한다고 백엔드나 UI 상호작용까지 구현된 것은 아니다.

## 1. 사용자 흐름

```text
SCR-01 Archive
  └─ 자료 묶음 생성 → 사진·메모 등록 → 원본 확인
      └─ SCR-02 Investigation
          ├─ 단서 검토·수정·거절
          ├─ 연결 없음 → 수동 비교 / 다른 자료 선택 / 저장하고 종료
          └─ 연결 후보 → 근거 확인 → 질문에 사용 / 보류 / 거절
              └─ SCR-03 Conversation
                  ├─ 텍스트 답변 / 기억 안 남 / 답변 거절
                  └─ 증언 저장 및 수정
                      └─ SCR-04 Living Gallery
                          └─ 카드 편집 → 출처 확인 → 비공개 저장 → 재열기
```

사용자는 중간에 종료했다가 다시 들어올 수 있어야 한다. AI 호출 없이도 수동 기록·정정과 전시 편집은 계속할 수 있어야 한다.

**접근 경계:** Public Demo는 허가된 합성 자료만 읽기 전용으로 보여주며, 방문자에게 실제 계정의 자료나 DB 쓰기·Meta live 호출을 노출하지 않는다. Private Workspace는 Supabase Auth 로그인 후 본인 자료만 읽고 쓸 수 있다. 데모 화면의 조작이 영구 저장되거나 실제 AI 추론처럼 보이지 않도록 `SYNTHETIC / FIXTURE` 표기를 유지한다.

`SCR-02`와 `SCR-04`의 Figma 이미지 슬롯은 사진을 넣지 못한 플레이스홀더다. 실제 합성 데모 사진을 넣은 시각 완성본은 아니다. 현 서체·색은 디자인 제안이며 팔레트 확정 전이다.

## 3. 공통 인터랙션 규칙

### 3.1 정보와 상태의 분리

서로 다른 다음 세 축을 하나의 `status` 필드나 배지로 뭉개지 않는다.

- **정보 종류:** `observation` (원본 판독), `hypothesis` (추론), `testimony` (사람의 말).
- **사람의 검토:** 예를 들어 `unreviewed`, `corrected`, `rejected`, `accepted_for_inquiry`.
- **근거 유효성:** `current`, `needs_review`, `invalidated`.

연결 후보의 `accepted_for_inquiry`는 "질문에 쓰기로 선택"이라는 뜻이며 "가족사로 확정"이 아니다. 세 종류 모두 **텍스트 이름 + 구분 가능한 스타일**로 표기한다. 색상만으로 구분하지 않는다.

### 3.2 출처로 돌아가는 길

모든 관찰/가설/전시 콘텐츠의 출처를 선택하면 해당 자료와 정확한 버전으로 돌아갈 수 있어야 한다.

- 위치 좌표가 검증되지 않으면 임의의 정밀 박스를 만들지 않는다. 전체 이미지 근거와 대략적인 설명을 보여준다.
- 원본이 삭제됐거나 해당 판본이 비활성화됐다면 예전 인용을 최신 사실처럼 노출하지 않는다.
- 상충하는 관찰이나 증언이 있어도 한쪽을 자동으로 지우거나 합치지 않는다.

### 3.3 모든 화면이 지원할 공통 상태

| UI 상태 | 사용자에게 보여줄 내용 | 허용 동작 |
| --- | --- | --- |
| Empty | 왜 비어 있는지, 시작 동작 또는 자료 부족 | 업로드·직접 기록·다른 자료 선택 |
| Loading | 실제 진행 중인 작업 명칭, 완료 전임을 표시 | 무한 중복 실행 방지; 뒤로 이동 허용 |
| Partial | 성공한 결과와 실패한 결과를 분리 | 실패 항목만 재시도 |
| Error | 원인 범주(입력, 저장, 권한, 모델, 예산, 네트워크) | 안전한 재시도 또는 수동 우회 |
| No result | 실제 분석은 완료했으나 유의미한 단서/연결이 없음 | 수동 입력·다른 자료 비교 |
| Needs review | 기존 출처가 정정·삭제됐거나 새 근거와 충돌 | 검토 후 재저장 또는 관련 카드 제외 |
| Fixture / Replay / Live | AI 응답 출처 모드를 명시 | 실제 Meta 결과로 오해하지 않도록 라벨 유지 |
| Permission denied | 미인증·다른 사용자 자료·만료된 서명 URL | 로그인 또는 안전한 재요청; 데이터 자체는 노출하지 않음 |

저장 버튼의 "완료" 표현은 영구 저장 성공 응답 이후에만 표시한다. 재시도 시 중복 객체를 만들지 않도록 서버가 보호한다.

## 4. SCR-01 — Archive

**사용자 목표:** 새 개인 자료 묶음을 만들고 원본을 저장·분류·다시 열기.

**주요 블록**

- 인증된 사용자의 자료 묶음 선택/생성 및 이름 변경; 로그인 상태와 소유권을 서버가 검증.
- 사진·메모 이미지를 넣는 업로드 영역(JPEG/PNG/WebP 후보, 최종 한도는 기술 문서에서 확정).
- 직접 텍스트 메모 입력 기능.
- 원본 미리보기 그리드, 각 자료의 `asset_id`, 자료 종류, 업로드/분석 상태.
- 등록일, 사용자가 아는 사건·날짜 정보, 실제 촬영 메타데이터의 명확한 구분.
- "데모 자료" 표시(실제 사용자 자료와 별도 경계).

**행동과 결과**

- 새 묶음 → 서버에 Workspace 생성 후 ID로 이동.
- 파일 선택 → 임시 미리보기 → 서버에서 소유권 검증과 짧은 업로드 권한 발급 → Private Storage 직접 업로드(검증 대기) → 서버가 실제 파일·메타데이터를 검증하고 Asset/Revision을 활성화. 완료 전 UI에는 저장 성공을 표시하지 않는다.
- 실패한 파일은 이유를 표시하고 성공한 다른 파일은 보존.
- 파일을 다시 클릭 → 사용자 소유권·Storage 정책을 확인한 뒤 제한된 시간의 비공개 다운로드 경로로 조회. public static 폴더의 공개 URL 사용 금지.
- 메타데이터 수정 → 새 리비전으로 저장하고 기존 값 보존.
- 삭제 → 확인 후 접근 차단, 관련 증거와 전시의 재검토를 시작. 원본과 파생물 삭제 실패를 숨기지 않는다.

**완료 기준:** 재시작 후 업로드·미리보기·이름·메모가 남고, 인증하지 않은 사용자 및 다른 Workspace의 파일 접근이 차단된다. [E02, E09, E11, E13](implementation-plan.md)

## 5. SCR-02 — Investigation

**사용자 목표:** 두 개 이상 자료의 원본을 함께 보며 AI 제안과 사용자의 해석을 비교·선택한다.

**Figma 현재 시안:** 1440×900 데스크톱, 어두운 조사 테이블, 왼쪽 2개 이미지 자리, 오른쪽 관찰/연결 검토 패널. 이미지 플레이스홀더 및 비동작 버튼 상태.

**주요 블록**

- 원본 A/B 비교: 큰 이미지, 확대/원본 열기, 날짜 미확정 및 자료 유형 표시.
- 관찰 패널: OCR·간판·특징적인 물건·날짜 표기, 출처, 판독 한계, 원문, 정정 이력.
- 연결 패널: 공통 단서, 반대 근거, 누락된 정보, 검토 상태.
- 다음 행동: `질문에 사용`, `보류`, `연결 제외`, `직접 단서 추가`, `다른 자료 비교`.
- `fixture/replay/meta-live` 모드 라벨과 요청 상태(결과 없음 포함).

**행동과 결과**

1. `단서 분석` → 권한·자료 판본 확인 → 작업 생성 → 검증된 관찰 제안 저장. 실패 시 완료처럼 표시하지 않는다.
2. `정정` → 원문과 변경을 비교 후 저장 → 새 ObservationRevision/ReviewDecision → 관련 가설·질문·전시 `needs_review`.
3. `단서 거절` → 검토 결정 보존. 같은 입력 판본의 재분석에서 거절 단서를 승인된 사실처럼 재사용하지 않는다.
4. `연결 확인` → 근거 참조가 실제 존재하고 같은 자료 묶음인지 검증 → 지지/반대 근거와 함께 제시.
5. `질문에 사용` → 가설을 `accepted_for_inquiry`로 기록하고 질문 선택으로 이동. 가설의 정보 종류는 변하지 않는다.
6. `보류/제외` → 결정 기록. 동일한 원본·리비전 기반 제안이 사용자 의사에 반해 자동 복원되지 않는다.

**정상 분기:** 근거 없음/연결 없음이면 비어 있는 패널과 수동 비교를 제공한다. 같은 간판이라는 이유만으로 같은 날·행사·사람이라고 추정하지 않는다.

**완료 기준:** 사용자의 수정·채택·거절이 새로고침 후 유지되고, 잘못된 근거 ID·오래된 판본·다른 Workspace 자료는 거부된다. [E03–E05, E08, E14, E16](implementation-plan.md)

## 6. SCR-03 — Conversation

**사용자 목표:** 화면 복잡도를 줄이고 하나의 질문과 관련 사진에 집중해 증언을 기록한다.

**주요 블록**

- 현재 질문 한 개, 관련 사진(원본 출처 링크), '왜 묻는지'에 대한 근거.
- 질문 문구 편집·선택·완료 상태.
- 답변 입력, `기억 안 남`, `답변 원치 않음`의 별도 선택.
- 발화자 표시명·기록자(주사용자)·전달 형식(직접 들음/전해 들음) 명시.
- 후속 단계에 녹음/전사 시작·검토·정정 블록 추가. M1b에서 오디오 성공처럼 표시하지 않는다.

**행동과 결과**

- 질문 선택/수정 → Question 판본 업데이트, 출처 관계 보존.
- 텍스트 답변 저장 → 발화자/기록자와 입력 문구 그대로 TestimonyRevision 생성. '누가 기억한다고 말했다'는 기록이지 AI 검증 사실이 아니다.
- 기억 안 남/답변 거부 → 상태로 저장하고 다음으로 이동 또는 종료 가능.
- 증언 정정 → 이전 내용 유지, 현재 버전과 전시 `needs_review` 전파.
- 마이크 거부/전사 실패(후속) → 사용자 동의를 우선하고 텍스트 입력으로 전환.

**완료 기준:** 발화자·기록자 구분이 유지되고, 비응답 및 상충 증언이 손실 없이 남는다. [E06, E07, E12](implementation-plan.md)

## 7. SCR-04 — Living Gallery

**사용자 목표:** 기록과 증언을 작은 개인 전시로 읽고 수정하며, 문장마다 출처로 돌아간다.

**Figma 현재 시안:** 1440×900 데스크톱, 밝은 전시 배경, 큰 대표 사진 자리, 전시 서술·열린 질문·출처 하단 띠. 사진은 미업로드 플레이스홀더이며 클릭 동작은 아직 없음.

**주요 블록**

- 전시 제목, 대표 이미지, 자료 카드 정렬·선택.
- `관찰`, `가족이 남긴 말`, `아직 모르는 점`을 구분한 편집 가능한 설명.
- 사용자 선택 증언을 적절히 인용(발화자/기록자 구분).
- 출처 칩: 클릭 시 원본 사진/메모/증언의 판본 및 원래 문맥으로 이동.
- 소유자만 가능한 비공개 저장/다시 열기/정정/삭제, 근거 변경으로 인한 재검토 경고.
- 공개 합성 전시는 로그인 없이 열람 가능하되 개인 Workspace와 데이터·URL을 공유하지 않으며 수정·기록은 비활성.

**행동과 결과**

- `전시 만들기` → 사용자가 선택한 자료·검토한 단서·증언만으로 카드 초안 구성. 문학적 허구로 채우지 않는다.
- `저장` → Exhibit와 ExhibitRevision 저장. 변경된 근거를 사용하는 카드가 있으면 재검토 상태 유지.
- `출처 보기` → 존재·권한·판본 검사 후 원래 자료로 이동. 원본이 삭제되면 잘못된 최신 인용으로 유지하지 않는다.
- `카드 수정/삭제` → 사용자의 서술도 사용자 입력 출처로 남기고 이전 판본 관리.

**완료 기준:** 전시가 재실행 후 열리고, 모든 근거 링크가 작동하거나 유효하게 비활성화된다. [E01–E03, E11, E14](implementation-plan.md)

## 9. 상호작용 세부 규칙

### 저장 충돌과 중복

- 사용자가 같은 버튼을 연속 누르면 진행 중 상태를 표시하고 중복 객체 생성을 막는다.
- 이미 수정된 판본에 오래된 요청이 도착하면 `revision conflict`를 알려준다. 사용자의 편집을 덮어쓰지 않는다.
- 파일 업로드 일부 실패와 AI 분석 일부 실패는 서로 다른 오류로 표시한다.

### AI와 프롬프트 주입

- 업로드 사진·메모 속 명령문은 사용자의 데이터로만 취급한다. 모델의 시스템 지시로 해석하지 않는다.
- 생성된 질문이 과거 추정으로 확정 날짜/장소를 요구하지 않도록 스키마·검토 UI를 제공한다.
- `live`가 실패하면 `fixture`로 조용히 바꾸지 않는다.

### 접근성과 반응형

- 데스크톱: 원본 A/B와 근거 패널이 동시에 보이는 구성을 우선한다.
- 모바일: 한 장의 원본·한 질문·한 답변에 집중한다. 두 이미지 비교는 순차 탐색으로 축소 가능하되 출처를 잃지 않는다.
- 키보드 초점, 비활성화된 동작의 이유, 오류 텍스트, 원본의 대체 텍스트, 축소 애니메이션 설정을 고려한다.
- 기본 UI/시연 언어는 영어다. 한국어 기록 입력과 이름의 원문은 보존하고, 영어 UI와 화면 크기를 모두 테스트한다.

## 10. 아직 Figma에서 확정되지 않은 항목

- `SCR-01`과 `SCR-03`의 레이아웃·상태 화면.
- `SCR-02`와 `SCR-04`의 사진 자산 및 실제 데이터로 채워진 변형.
- Colours / typography variant, 특히 최종 팔레트 선택.
- 반응형 주요 breakpoint, 로딩/빈 상태/모델 실패 상태.
- 클릭 가능한 프로토타입의 화면 전환과 검토 액션.
- 로그아웃·만료된 세션·오류·공개 데모의 수정 불가 상태 및 비공개 파일 권한 거부 화면.

이 항목들은 제품 핵심 기능 구현을 시작하지 못하게 하는 조건은 아니다. 초기 구현은 이 문서의 상태/행동을 우선하고, Figma 시안은 확정되지 않은 시각적 방향으로 취급한다.
