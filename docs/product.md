# Trace & Tell — 제품 요구사항 (PRD)

- **상태:** v0.2 · 배포 우선 제품 방향 합의 · 구현 전 · 2026-10-28
- **대상:** Meta Global AI Developer Hackathon 2026, Indie Developer / Build for Your World
- **제품명:** Trace & Tell은 작업명이다. 최종 신청서 입력명은 별도로 확인하지 않았다.
- **문서 소유:** 이 문서는 구현 결과나 대회 공식 규정이 아닌 제품 요구사항 제안이다.

## 1. 문제와 핵심 약속

사진·손글씨 메모·편지 같은 기록은 보존되지만, 그 안의 장소·행사·사람·사물에 대한 맥락은 구술자의 기억과 함께 잃을 수 있다.

**핵심 약속:** 기록 정리자가 흩어진 자료에서 검토할 가치가 있는 단서를 찾아, 가족이나 지인에게 **물어볼 만한 질문**을 발견하고, 들은 답변을 출처와 불확실성까지 함께 보존할 수 있게 한다.

- 단순 사진 자동 정리, 얼굴 인식, 가계도 자동 완성이 핵심이 아니다.
- AI가 가족사를 단정하지 않는다. 관찰·연결 가설·사람의 증언을 다른 종류로 유지한다.
- 모름·연결 없음·답변 거절·서로 다른 증언도 온전한 결과로 취급한다.
- 개인적 사연이나 민감한 가족 정보는 공개 데모·저장소에 기본 포함하지 않는다.

## 2. 첫 사용자와 이용 환경

**기록 정리자(주사용자)** 한 명이 사진과 메모를 모아 조사하고, 가족 구성원이나 해당 시기를 아는 사람에게 직접 질문한다. 초대·계정 공유가 아니라 주사용자가 답변을 입력하거나 명시적인 동의를 받아 녹음하는 흐름부터 구현한다.

- 조사 작업: 데스크톱 웹을 우선한다. 자료 2개 비교, 단서 검토, 연결 근거가 주요 작업이다.
- 가족에게 질문하기: 모바일에서도 읽기 쉬운 집중 화면으로 제공한다.
- 최종 전시: 넓은 화면에서는 박물관·디지털 갤러리 느낌, 모바일에서는 가독성과 출처 탐색을 우선한다.
- **UI 언어:** 영어를 기본으로 설계하되 한국어 입력과 원본 문구를 허용한다. 번역·한국어 OCR 품질은 미검증이다.
- **공개 합성 데모:** 로그인 없이 읽기 전용 전시·조사 과정을 살펴볼 수 있다. 공개 방문자에게 개인 자료·영구 쓰기 권한·무제한 모델 실행은 제공하지 않는다.
- **비공개 작업 공간:** 이메일 로그인으로 인증된 주사용자만 자료 업로드·수정·출처 확인·저장을 수행한다. 실제 권한 격리는 배포 전에 테스트한다.

## 3. 한 가지 완전한 사용자 여정

다음 사례는 **구현·평가에 사용할 합성 자료 시나리오**이며 실험 결과가 아니다.

1. 기록 정리자가 개인 자료 묶음 하나를 만든다.
2. 일부 글자가 흐릿한 상점 사진 두 장과 메모 이미지 한 장, 관련 없어 보이는 사진 한 장을 업로드한다.
3. 모델이 글자·간판·특징적인 물건 등 **관찰 가능한 단서**를 제안한다. 판독 불가를 인정한다.
4. 기록 정리자가 원본과 단서를 비교하고 오독 한 건을 수정한다. 원 제안과 수정의 이력을 구분한다.
5. 시스템이 서로 다른 자료의 공통 단서를 근거로 연결 후보를 만든다. 지지·반대·부족한 근거를 표시한다.
6. 기록 정리자가 연결 하나를 **질문에 사용**하기로 하고 무관한 연결은 거절한다. 이 결정은 역사적 사실의 확정이 아니다.
7. 시스템이 유도하지 않는 개방형 질문을 제안한다. 사용자가 수정·선택한다.
8. 기록 정리자가 가족의 발화를 텍스트로 남긴다. 발화자와 기록자를 구분한다. 모름/거절도 허용한다.
9. 선택한 사진·관찰·증언·남은 의문으로 작은 비공개 전시를 만든다.
10. 새로고침 후에도 열람·수정할 수 있고, 전시 내용에서 원본·증언으로 돌아갈 수 있다.
11. 단서/증언을 정정하면 관련 연결과 전시는 **재검토 필요**로 변경된다.

**데모의 결정적 순간:** 서로 무관해 보이던 두 기록에서 근거가 드러나고, 사용자가 연결을 검토한 후 사람에게 물어볼 질문을 얻는다.

| --- | --- | --- |
| 필수 | 이메일 인증, 작업 공간 소유권/RLS, Private Storage, 사진/메모 업로드·재조회 | M1a |
| 필수 | 원본 옆에서 관찰 검토·정정·거절 | M1b (fixture), M2 (live) |

| 필수 | 출처가 있는 전시 카드 편집·저장·다시 열기 | M1b |
| 필수 | 관찰·가설·증언·AI 실행 모드 구분, 재검토 이력 | M1b–M2 |
| 필수 | 실제 Meta 모델 경로와 오류·사용량 검증 | M2 |
| 이후 | 동의 기반 녹음, 전사 초안, 사람의 전사 교정 | M3 (시간과 지원 여부에 따라) |
| 필수 | 합성 자료 기반 공개 읽기 전용 데모(개인 데이터와 분리) | M1a–M4 |
| 필수 | 실제 온라인 배포 전에 사용자 승인·RLS/파일 격리 검증 | M1a (배포 관문) |
| 이후 | 삭제·재시도·접근 제어 심화 및 개인정보 처리 검증 | M3 |
| 제외 | 얼굴 신원 판정, 혈연 자동 추정, 의료/인지능력 효과 주장 | 전체 범위에서 제외 |
| 제외 | 공개 가족 공유 링크, 실시간 공동 편집, 대규모 가계도, 3D 전시 | 초기 해커톤 MVP에서 제외 |
| 제외 | 대규모 그래프 DB·벡터 검색·모든 자료 쌍에 대한 과도한 모델 호출 | 초기 해커톤 MVP에서 제외 |

**모델 검증 실패 시 조정:** 자동 연결이 근거를 안정적으로 만들지 못하면, 사용자가 두 자료를 선택하게 하고 AI가 그 관계의 근거·반대 근거·질문만 제안하는 경로로 좁힌다. 자동 판독이 약하면 사용자 전사·정정 경로를 강화한다. 이런 축소는 제품 목표를 유지하는 범위에서 명시적으로 결정한다.

## 5. 정보·윤리 요구사항

- `observation`: 원본에 보이는 내용의 판독·서술. AI 또는 사용자가 제안했을 수 있고 틀릴 수 있다.
- `hypothesis`: 단서로부터 생성된 연결 추론. 사람이 채택해도 `hypothesis` 그대로다.
- `testimony`: 발화자가 무엇을 기억/전달했다고 했는지에 대한 기록. 독립 검증된 역사적 사실과 다르다.
- 사용자의 변경은 모델 출력을 조용히 덮어쓰지 않는다.
- 근거·원본의 수정/삭제는 관련 가설·질문·전시의 유효성에 반영된다.
- 얼굴 유사도로 신원·친족 관계를 추론하지 않는다.
- 실제 가족의 사진·목소리·민감한 기록은 적절한 동의, 저장 격리, 모델 처리 조건을 확인하기 전 사용하지 않는다.
- 공개 시연 자료는 합성 자료나 사용 허락이 확보된 자료만 사용한다.
- Meta Contributor 모드에는 개인·기밀 자료를 보내지 않는다. Meta Standard는 첫 모델 경로의 후보이나, 실제 계정 권한과 허용된 개인정보 처리 조건을 검증하기 전에는 합성 자료만 처리한다.
- 공개 데모 데이터와 인증된 개인 Workspace의 DB·Storage 접근 경로를 분리하고, 공개 모드에서는 백엔드 쓰기와 실시간 유료 호출을 기본 차단한다.

## 6. 성공 기준과 검증의 구분

**개발 성공 (E2E)**

- 새 자료 묶음에서 업로드 → 단서 → 연결 후보 → 질문 → 텍스트 증언 → 전시가 실제 UI와 영구 저장을 거쳐 이어진다.
- 새로고침과 서버 재시작 이후 원본·정정·검토·전시가 유지된다.
- 모든 중요한 주장/가설/전시 카드에서 실제 존재하는 근거로 이동할 수 있다.
- 비슷하지만 무관한 자료에 대한 `no_connection`이 허용되며, 사용자 거절·수정이 보존된다.
- 실제 Meta API 호출과 fixture 테스트의 결과·로그가 분명히 분리된다.

**모델 평가**

- 합성 자료의 정답표를 모델 입력에서 분리한 뒤, 관찰의 정확성/불확실성 표현/근거 타당성/허위 연결/질문의 유도성을 사례별로 평가한다.
- 샘플 수, 실패 사례, 사용 모델 ID, 요청 모드, 실제 지연과 사용량을 남긴다. 검증 전에는 어떤 정확도·지연·성공률도 주장하지 않는다.

**대회 제출 성공**

- 주최 측의 최신 Official Rules와 참가자용 제출 폼 조건을 실제로 확인하고, 필요한 결과물을 마감 전에 제출한 증거를 확보한다.
- 공식 공개 페이지의 제출 마감은 **2026-11-04 21:00 ET = 2026-11-05 11:00 KST**이다. 변경 시 공식 출처를 다시 확인한다.
- 제출 완료와 심사 결과는 별개의 상태로 기록한다.

자세한 E2E 수용 기준 ID는 [구현·검증 계획](implementation-plan.md)에서 관리한다.

## 7. 시각 방향 및 설계 출처

**Digital Family Museum × Interactive Research Archive**

- `SCR-02 Investigation`: 어두운 조사실, 원본 비교, 근거 표시, 연결 검토. LetterStori.es와 연결 탐색 전시형 레퍼런스의 방향을 참고한다.
- `SCR-04 Living Gallery`: 밝은 박물관 전시, 커다란 사진, 세리프 제목, 간결한 캡션과 출처. Public Domain Image Archive의 에디토리얼 아카이브 방향을 참고한다.
- 시각 팔레트는 **미확정**이다. 현재 Figma 토큰은 시안이며, 구현 시 교체 가능한 테마 변수로 관리한다.
- [Figma Investigation](https://www.figma.com/design/a4nRD7Ixyy2ue7mAL0meZU?node-id=3-2) · [Figma Living Gallery](https://www.figma.com/design/a4nRD7Ixyy2ue7mAL0meZU?node-id=3-45)
- 현재 Figma의 사진 영역은 플레이스홀더이고 클릭 가능한 최종 프로토타입/구현이 아니다.


## 8. 확정된 방향과 남은 확인

**사용자가 합의한 방향:** 배포 우선 · Next.js/TypeScript/Tailwind · Supabase PostgreSQL/Auth/Private Storage · Vercel 배포 후보 · 영어 UI · 공개 읽기 전용 합성 데모 + 인증된 비공개 작업 공간 · 무료 플랜 우선(유료 전환은 별도 승인). 시각 팔레트는 임시 토큰을 사용한다. Supabase Seoul 프로젝트 생성은 직접 확인했지만 실제 DB 스키마·배포 완료를 뜻하지 않는다.

**아직 외부 확인이 필요한 것:**

1. 참가자용 Official Rules 수락, 실제 제출 폼, 영상 길이, 코드 공개·라이브 URL 요구.
2. Vercel Hobby 이용조건이 상금이 있는 개인 비상업 해커톤 데모에 해당하는지와 현재 계정 플랜.
3. 합성 사진·메모의 실제 파일, 사용 권리 및 정답표 분리.
4. 계정에서 접근 가능한 Meta 모델 ID, 이미지 입력·구조화 출력, 실제 소액 호출 예산.
5. 음성 전사 지원 및 품질, 최종 팔레트. 이들은 첫 영속화 구현을 막지 않는다.
